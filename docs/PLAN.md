## 1. 과제 정의 (PDF 기준)

### 1.1 주제와 문제 정의 (p.8)
- **주제**: KOSPI 지수와 상품지수의 상승 가능성(Probability) 예측
- **분석 단위**: Daily
- **문제 유형**: 이진분류 2개 (Multi-target, 타깃별로 따로 학습)
  - `Target_1`: D+3일 KOSPI 지수 상승 여부 (1 = 상승, 0 = 보합·하락), 원변수 `FI_KOSPI`
  - `Target_2`: D+3일 건강식품 지수 상승 여부 (1 = 상승, 0 = 보합·하락), 원변수 `SH2_쇼핑2_식품_건강식품`
- **설명 변수**: 거시경제·금융시장·소비 트렌드·기상 요인 284개 (`Weekday` 포함, `Time_step` 제외)
- **기간**: 학습 924일 / Public 평가 100일 / Private 평가 200일
- **평가 지표**: AUC (ROC Curve 아래 면적)

| | 모델 설계 완성도 | 학습 알고리즘 설계, **검증 방법 설계**, 모델 최적화 노력 | |
| | 분석 결과 전달력 | 결과 커뮤니케이션, 모델 구조 설명 | |

### 1.3 제출물 (p.10, p.11, 베이스라인 노트북)
1. **모델 결과 보고서**: 전체 모델 파이프라인을 이해할 수 있는 자유 양식 **PDF**
2. **모델 개발 코드**: **Private Score를 재현할 수 있는** `.py` 또는 `.ipynb`
3. **예측 결과 CSV**: 컬럼은 `Time_step, pred_1, pred_2`이고, `pred_*`는 **0 이상 1 이하의 실수**
   - Public: `public_<반>_<이름>_<회차>.csv` (예: `public_1반_홍길동_1.csv`). **최대 4회 제출 가능** (확인됨)
   - Private: `private_<반>_<이름>.csv` (예: `private_1반_홍길동.csv`)

### 1.4 규칙 (p.11)
1. **제공된 데이터 외에 외부 데이터 사용 금지**
2. **평가용 데이터는 학습에 쓸 수 없음** (Data Leakage)
3. 시계열이므로 **Shuffle 금지**, 시간 순서를 유지해야 함 (베이스라인 주석)

### 1.5 PDF의 맥락 (p.3~7, p.12~15 Appendix)
- 배경: 오픈데이터 융합 → 피처 자동화 → Auto Modeling → 인사이트로 이어지는 파이프라인. 문제 유형은 Predictive Modeling이며 **예측 성능 중심으로 평가**한다.
- 데이터 카테고리: FI_(금융), SH1_/SH2_(쇼핑 클릭량 Level 1/2), KE_(검색어), WE_(날씨). 월 단위인 PU_(공공)는 이번 과제에서 제외됐다.
- Appendix 사례(유가 예측, 쇼핑지수 예측)의 Feature Importance 상위 이름은 `rt_01_*`, `rt_07_*`, `ma_30_*`, `cv_30_*`, `rt_8330_*` 형태다. 강사가 기대하는 피처 엔지니어링이 **변화율(rt), 이동평균(ma), 변동계수(cv) 같은 시계열 파생변수**라는 강한 힌트로 본다. 같은 사례에서 "금융 피처만 쓴 경우보다 전체 피처를 쓴 경우 AUC가 올랐다"(0.969 → 0.977)는 비교 실험이 보고서의 모범 형식으로 제시됐다.

## 4. 데이터 탐색으로 확인한 사실 (지시받지 않았지만 반드시 알아야 할 것)

### 4.1 타깃의 원변수가 제거되어 있다
`FI_KOSPI`와 `SH2_쇼핑2_식품_건강식품`은 **세 CSV 어디에도 없다** (FI 컬럼은 PDF의 19개가 아니라 18개, SH2는 189개가 아니라 188개). 따라서 타깃을 재구성하거나 과거 원변수로 자기회귀 피처를 만드는 방식은 **불가능**하다. 대리변수로 간접 예측해야 한다.

### 4.2 설명변수는 0~1 Min-Max 스케일이고, 스케일은 학습+테스트 전체 기간에 맞춰져 있다
- 변수 설명서에는 "표준화 처리된 값"이라고 적혀 있지만, 실제 값은 **[0, 1] 범위**다. 전체 1,124일 기준으로 min = 0인 컬럼이 99.6%, max = 1인 컬럼이 97.9%다. train만 보면 각각 89.8%, 57.2%에 그친다.
- 의미: 스케일링은 출제 측에서 끝냈다. 우리가 다시 스케일링할 경우 **train에서만 fit**해야 한다 (선형모델용). 트리 모델에는 스케일링이 필요 없다.

### 4.3 Weekday: 1 = 일요일 … 7 = 토요일, 주말 행이 포함되어 있다
- 1,124일이 끊김 없이 이어지고 Weekday는 1→7로 순환한다. Weekday 1과 7에서 `FI_Dow`·`FI_Nasdaq`의 전일 대비 변화가 **100% 0**이므로 1 = 일요일, 7 = 토요일이다. 주말의 시장 값은 forward-fill되어 있다.
- **Target_2는 요일로 거의 결정된다.** 요일별 상승 비율은 다음과 같다.

  | Weekday | 1 일 | 2 월 | 3 화 | 4 수 | 5 목 | 6 금 | 7 토 |
  |---|---|---|---|---|---|---|---|
  | Target_2 = 1 비율 | 0.92 | 0.17 | 0.05 | 0.02 | 0.19 | 0.95 | 0.98 |
  | Target_1 = 1 비율 | 0.52 | 0.49 | 0.50 | 0.52 | 0.58 | 0.50 | 0.51 |

  금·토·일의 D+3은 월·화·수다. 건강식품 클릭량에는 강한 주간 패턴이 있다(평일 초반이 높음). 요일 하나만으로 시계열 검증 AUC가 **0.926**이다. 성능을 더 올릴 여지는 **같은 요일 안에서의 순위**, 특히 불확실한 월(0.17)과 목(0.19)에 있다.
- 베이스라인은 Weekday를 숫자(1~7)로 넣는다. 트리 모델은 버티지만 선형모델에는 **원-핫 인코딩**이 필요하다.

### 4.4 라벨이 3일씩 겹친다 → 검증 시 gap이 필요하다
- Target_1의 자기상관은 lag1 = 0.47, lag2 = 0.25, lag3 ≈ 0이다. D와 D+1의 라벨이 2일을 공유하기 때문이다.
- Train/Valid 경계에서 **최소 3일을 비워야**(gap = 3, purging) 검증 점수가 부풀려지지 않는다. 베이스라인의 70/30 분할에는 gap이 없다.

### 4.5 Target_1은 신호가 매우 약하고 노이즈가 크다
시계열 5-fold(fold당 100일, gap = 3) 간이 실험 결과:

| 피처셋 | 모델 | Target_1 평균 AUC (fold 범위) | Target_2 평균 AUC |
|---|---|---|---|
| 원본 전체 (베이스라인 방식) | RF | 0.499 (0.41~0.56) | 0.935 |
| 요일 원-핫만 | LR | 0.483 | 0.935 |
| 요일 + FI 1일·3일 차분 | RF | 0.544 | 0.935 |
| 원본 + 요일 + FI 차분 | RF | **0.575** (0.47~0.66) | 0.935 |

- 원본 수준값(level) 대신 **변화량(차분, 변화율) 피처**를 쓰면 Target_1에 약한 신호가 생긴다. Appendix 힌트와 같은 방향이다.
- 100일 구간의 AUC가 fold마다 ±0.07씩 흔들린다. 따라서 **Public 점수(100일)도 노이즈가 크고**, Public 순위에 맞춘 튜닝은 위험하다.
- 배점은 두 타깃의 평균이다. Target_2는 이미 천장 근처이므로 **Target_1을 0.50에서 0.55~0.60으로 올리는 것이 정량 점수에 가장 큰 영향**을 준다.

### 4.6 테스트 기간은 COVID-19 확산기로 추정 → 심한 분포 이동
- `KE_코로나`는 Time_step 904부터 0보다 커지고 939에서 최대가 된다. `KE_QR체크인`은 train 전체가 0(상수)이고 1037부터 값이 생긴다.
- 실제 사건(국내 첫 확진 2020-01-20, 대구 확산 2월 말, QR 체크인 도입 6월)과 맞춰 보면 **(추정)** 학습 기간은 2017-08 ~ 2020-02 초, 테스트 기간은 2020-02 ~ 2020-08이다. 테스트에는 2020년 3월 KOSPI 폭락과 V자 반등이 들어 있다.
- 테스트 평균이 train 표준편차의 1배 넘게 이동한 컬럼이 154개, 2배 넘게 이동한 컬럼이 88개다. 특히 `KE_온라인강의`(97σ), `KE_zoom`(55σ), `KE_코로나`(36σ), `KE_재택근무`, `KE_비대면`, `KE_화상회의`가 크다.
  → 트리 모델은 train 범위 밖의 값을 외삽하지 못한다. 수준값 피처는 이동에 취약하므로 **변화율이나 요일 대비 상대값처럼 스케일에 무관한 피처**를 쓰고, 드리프트가 심한 피처는 제거 후보로 둔다. 이 판단은 "Feature Selection" 정성 평가 항목의 좋은 근거가 된다.
- `KE_QR체크인`은 train에서 상수이므로 제거한다 (베이스라인의 단일값 처리 로직도 이를 잡아낸다).

### 4.7 테스트에 타깃이 없으므로 타깃 lag 피처는 쓸 수 없다
Target_2의 lag7 자기상관이 0.70으로 높지만, 테스트 구간의 타깃은 NaN이다. 과거 타깃을 피처로 쓰면 **테스트 첫 며칠 외에는 값을 채울 수 없다.** 사용하지 않는다.

### 4.8 베이스라인 노트북의 한계 (개선 포인트 = 보고서 소재)
| 문제 | 영향 | 개선 |
|---|---|---|
| 최종 모델이 **train의 70%로만** 학습된다 | 최근 30%(가장 테스트와 가까운 시기)를 버린다 | 검증으로 설정을 확정한 뒤 **train 전체로 재학습**해서 제출 |
| Train/Valid 사이에 gap이 없다 | 검증 점수 과대평가 | gap = 3 |
| 단일 holdout 1회 | 노이즈가 커서 의사결정이 불안정하다 | TimeSeriesSplit 다중 fold의 평균과 분산 |
| 수준값 피처만 사용 | 비정상 시계열이고 드리프트에 취약하다 | 변화율, 이동평균, 변동성 파생변수 |
| Public/Private 전환을 주석으로 한다 | 실수 위험 | Private 하나로 예측하고 앞 100행으로 Public 생성 |
| Missing 처리 셀 | train 결측이 0개라 실제로 아무 일도 안 한다 | 그대로 두되, 파생변수 초반 NaN 처리를 설계해야 함 |

| 행위 | 판단 | 근거 |
|---|---|---|
| 테스트 행의 피처로 **과거 방향** 롤링·lag 피처 만들기 (예: D-1, D-7 대비 변화율) | **허용으로 해석** (단, 확인 권장) | 예측 시점에 이미 관측된 과거 피처만 쓰고 타깃은 쓰지 않는다. fit이 없다. 베이스라인 노트북도 셀 4에서 train과 test를 이어 붙여 `Time_step`으로 정렬하므로, 함께 처리하는 것을 전제한 구조로 보인다. 금지될 경우 test 행에서는 변화량 피처를 계산할 수 없어 Target_1의 신호(4.5)를 대부분 잃는다. |
| 스케일러, 인코더, 피처 선택, PCA 등을 **테스트 포함 데이터로 fit** | **금지** | "평가용 데이터는 학습에 활용 불가" |
| 테스트를 이용한 pseudo-labeling, adversarial validation 기반 재학습 | **금지** | 같은 이유 |
| 미래 방향 피처 (D+1 이후 값 사용) | **금지** | 실제 운영에서 불가능하고 누수다 |

## 6. 수행 계획

### 6.1 전략 원칙
1. **검증 체계를 먼저, 모델은 나중에.** Target_1은 노이즈가 커서 검증이 부실하면 운을 실력으로 착각한다.
2. **타깃별로 다른 전략을 쓴다.** Target_2는 요일을 축으로 요일 내 순위를 정교화한다. Target_1은 약한 신호를 견고하게 잡는다(정규화, 앙상블, 적은 피처).
3. **드리프트에 강한 피처를 우선한다.** 수준값보다 변화율, 요일 대비 상대값을 쓴다.
4. **Public 점수에 휘둘리지 않는다.** 의사결정은 내부 CV 평균과 분산으로 한다. Public은 파이프라인 정상 동작을 확인하는 용도다.
5. **모든 실험을 기록한다.** 정성 40점의 재료이고, 보고서의 "모델 최적화 노력" 근거가 된다.

### 6.2 단계별 계획

**Phase 0. 환경과 재현성 기반**
- 데이터를 워크트리 `data/raw/`로 복사하고 `.gitignore`에 데이터와 산출물을 등록한다.
- `requirements.txt`(버전 고정)를 만들고 seed를 고정한다.
- 검증: 깨끗한 환경에서 베이스라인 노트북이 그대로 돌아간다.

**Phase 1. 베이스라인 재현과 평가 하네스**
- 베이스라인을 그대로 재현해 기준점을 기록한다 (현재 측정값: valid AUC T1 = 0.510, T2 = 0.942).
- 공통 평가 함수를 만든다. `TimeSeriesSplit(n_splits=5, test_size=100, gap=3)`로 타깃별 AUC 평균과 표준편차를 낸다. 보조로 **train 마지막 200일 holdout**을 둔다 (Private 길이 모사).
- 제출 파일 검증기를 만든다: 행 수, `Time_step` 순서와 집합이 샘플과 같은지, 컬럼명, 값이 [0, 1] 범위인지, NaN 없음.
- 검증: 하네스로 잰 베이스라인 점수가 노트북 값과 일관된다.

> **Phase 0~1 완료 (덩어리 1)**
> - 노트북 재현: 70/30 AUC가 T1 0.5099, T2 0.9422로 노트북과 같다. Public 예측값 차이는 최대 1e-16이다.
> - 재실행하면 제출 파일과 채점 결과가 바이트 단위로 같다. 테스트 19개 통과.
> - **베이스라인 자체 채점 (앞으로 모든 개선의 기준점)**:
>
>   | 방식 | Target_1 | Target_2 | 평균 |
>   |---|---|---|---|
>   | cv5 (100일 × 5, gap 3) | 0.492 ± 0.102 (0.347~0.595) | 0.939 ± 0.031 | **0.716** |
>   | holdout200 (마지막 200일) | 0.554 | 0.920 | 0.737 |
>
> - Target_1은 fold별 편차가 ±0.10으로 매우 크다. 개선 여부는 평균뿐 아니라 fold별로 일관되게 나아졌는지로 판단한다.
> - Public 1회차 파일: `outputs/submissions/baseline/public_반_이름_1.csv` (train 전체로 재학습)

**Phase 2. EDA (보고서용 근거 확보)**
- 타깃 분포, 요일 효과(4.3), 라벨 겹침(4.4), 드리프트(4.6), 카테고리별 타깃 상관을 정리한다.
- 대리변수 탐색: Target_1과 FI 변화율, Target_2와 식품·건강 계열 변화율의 관계를 본다.
- 산출물: 보고서에 넣을 핵심 그림 5~7개.

> **Phase 2 완료 (덩어리 2)**: `notebooks/01_eda.ipynb`, 그림 6개 (`outputs/figures/`)
> - 방법: 변수 하나씩 AUC를 계산했다 (원래값 + 1·3·7일 변화량, 1,128개). 타깃을 시간축으로 순환 이동시켜 **우연 기준선**(최대 |AUC−0.5|의 95분위)을 만들고 비교했다. Target_2는 요일 효과를 제거한 "같은 요일끼리 AUC"를 썼다.
> - **Target_1**: 기준선(AUC 0.597)을 넘은 후보는 3개(S&P500 1·3일 변화, Dow 1일 변화)다. **상위 6개가 모두 미국 지수 변화량**이고, 전후반 모두 AUC 약 0.58~0.60이다. 요일 효과는 없다. 3개월 단위로 상승 비율이 0.37~0.66까지 출렁인다.
> - **Target_2**: 요일 패턴이 train 세 구간에서 거의 같다(금·토·일 ≥ 0.91, 화·수 ≤ 0.07). 같은 요일 안에서 기준선(0.658)을 넘은 후보는 63개로, 쇼핑 Level 1과 검색어의 변화량 같은 **전체 트래픽 흐름** 신호다.
> - **드리프트 (train 내부, 마지막 200일 vs 이전)**: 원래값은 282개 중 115개가 SMD > 1이고, 미국 지수는 값의 50% 이상이 이전 범위 밖이다. 변화량은 SMD 중앙값이 0.01~0.06으로 안정적이다.
> - **Phase 3 방향 (확정)**:
>   - 변화량 중심으로 간다 (원래값 포함 여부는 CV로 비교).
>   - Target_1은 미국 지수 변화량 파생에 집중한다.
>   - Target_2는 요일 원-핫에 카테고리별 집계 트래픽 변화량과 같은 요일 대비 지표를 더한다.
>   - EDA 순위는 train 전체로 계산했으므로, 피처 수를 적게 유지하고 최종 선택은 CV fold 안에서 한다.

**Phase 3. Feature Engineering (과거 방향만)**
- 공통 파생: `rt_k`(k일 변화율·차분, k ∈ {1, 3, 7}), `ma_k`(이동평균, k ∈ {7, 30}), `cv_k`(변동계수), 이동평균 대비 괴리. Appendix 명명 규칙과 맞춘다.
- Target_2 전용: **요일 원-핫**, D+3 요일, 식품·건강 계열의 **같은 요일 대비 상대값**(D vs D-7), 최근 추세.
- Target_1 전용: 미국 지수·환율·유가·금리의 1·3일 변화, 최근 변동성.
- 경계 처리: train과 test를 시간순으로 이어 붙인 뒤 **과거 방향으로만** 계산한다. 그래야 test 첫 행도 train 마지막 행을 이용해 정상 계산된다. 초반 NaN 구간은 제거하거나 train 통계로 대체한다.
- 검증: 단위 테스트로 "피처 값이 미래 행에 의존하지 않음"을 확인한다 (미래 행을 바꿔도 과거 피처가 불변인지).

**Phase 4. Feature Selection**
- 1차: 상수·준상수 제거, 드리프트 심한 수준값 제거. 드리프트는 **train 내부에서만** 판단한다 (예: train 앞 구간과 마지막 구간의 분포 차이). 도메인 근거로 보완한다 (예: 코로나 관련 검색어는 train 말미부터 급변). 테스트 분포를 보고 피처를 고르면 5.1의 "테스트로 피처 선택 금지"에 걸린다.
- 2차: 고상관 중복 제거, CV fold 안에서 측정한 permutation importance나 중요도 기반 선택. 선택 과정은 반드시 **fold 내부에서** 수행해 누수를 막는다.
- 카테고리 ablation: Appendix 형식처럼 FI만, FI+SH, 전체를 비교한다.

**Phase 5. 모델링 (타깃별 독립)**
- 후보: L2/L1 로지스틱 회귀, RandomForest, ExtraTrees, Gradient Boosting(LightGBM, XGBoost, CatBoost). Target_1은 얕은 트리, 강한 정규화, 큰 `min_samples_leaf`를 쓴다.
- 하이퍼파라미터는 CV 평균 AUC로 고르되, 분산이 작은 설정을 우선한다. 탐색 범위는 작게 잡는다 (데이터가 924행이라 과적합 위험이 크다).
- 앙상블: 이질적 모델의 **rank 평균**을 쓴다. AUC는 순위 기반 지표라 확률 보정이 필요 없고 rank 평균이 안정적이다. seed 여러 개 평균도 한다.
- 검증: 타깃마다 베이스라인 대비 CV 평균이 개선됐는지, fold 분산이 줄었는지 확인한다.

**Phase 6. 최종 학습과 제출**
- 확정한 설정으로 **train 924행 전체에서 재학습**하고 `test_private.csv`를 예측한다. 앞 100행으로 Public 파일을 만든다.
- 제출 검증기를 통과해야 한다. 파일명 규칙: `public_<반>_<이름>_<회차>.csv`, `private_<반>_<이름>.csv`.
- **Public 4회 사용 계획.** Public은 100일짜리라 노이즈가 크다(4.5). 따라서 모델 선택이 아니라 **동작 확인과 큰 실수 탐지**에 쓴다.
  1. 1회차 (초반): 베이스라인을 train 전체로 재학습해 제출 → 제출 형식과 파이프라인이 정상인지, 기준점 확인
  2. 2회차 (중반): 피처 엔지니어링 반영 모델 → 내부 CV 개선이 Public에서도 방향이 맞는지 확인
  3. 3회차 (후반): 최종 후보 → 최종 Private 제출 직전 점검
  4. 4회차: 예비. 3회차에서 이상이 발견될 때만 사용
  - Public 점수가 내부 CV와 크게 어긋나면 먼저 **버그(정렬, 누수, 경계 처리)**를 의심한다. Public에 맞춰 튜닝하지 않는다.
- 재현성 확인: 깨끗한 환경에서 **처음부터 다시 실행해 Private CSV가 바이트 단위로 같은지** 확인한다.

**Phase 7. 보고서(PDF)와 코드 정리**
- 보고서 목차는 정성 평가 항목과 1:1로 맞춘다:
  1. 과제 이해와 데이터 개요
  2. **데이터 설계**: 전처리, Feature Extraction, Feature Selection (4장 발견 사항이 근거)
  3. **모델 설계**: 알고리즘 선택 이유, **검증 설계**(시계열 CV, gap, 누수 방지), 최적화 과정과 실험표
  4. 결과: 타깃별 CV, Public, 피처 중요도, 해석
  5. 한계와 개선 방향 (COVID 드리프트, Target_1의 낮은 예측 가능성)
- 코드: 실행 순서를 README에 쓰고, 한 번 실행으로 Private CSV가 나오는 구조로 만든다.
